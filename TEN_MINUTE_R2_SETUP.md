# Монтаж до 10 минут с iPad: Cloudflare R2 + Worker v8

## Что реально поддерживает эта версия

- До **10 минут общей длительности** выбранных видео, от 1 до 12 файлов.
- Большие исходники загружаются по 4 МБ **без Telegram Bot API**. Если Mini App закрылось, ранее переданные части можно восстановить.
- **Cloudflare KV** `UPLOADS` хранит только статус и небольшие метаданные. **R2** `VIDEO_FILES` хранит исходники, ZIP и итоговый Full HD.
- Без R2 старый режим до **500 МБ** сохраняется.
- **4 ГБ видео на один проект**, **100 МБ ZIP** и до **3 ГБ итогового мастер-MP4**. Это реальные предохранители нынешнего GitHub-hosted runner с ограниченным SSD. Это **не безлимит**: для файлов большего объёма нужен отдельный сервер монтажа или переработка обработки в потоковом режиме.
- Telegram получает отдельную версию MP4 до **48 МБ**, поскольку обычный облачный Bot API не принимает произвольно большой исходник. **Мастер** хранится в приватном R2 и доступен для загрузки через Mini App. Очень большие мастер-файлы на iPad могут потребовать дополнительной оптимизации загрузки, так как существующий интерфейс собирает MP4 из частей в браузере.

## Один раз подключить R2 в Cloudflare

1. Открой Cloudflare Dashboard на iPad → **R2 Object Storage**. Для включения R2 нужен аккаунт с R2 subscription. Это отдельное действие владельца; Cloudflare может попросить данные оплаты даже при работе внутри бесплатного объёма. **Не предоставляй ChatGPT реквизиты карты, пароли или токены.**
2. Создай **приватный bucket**, например `ai-montage-private`, в стандартном классе хранения.
3. В R2 добавь **Object Lifecycle Rule: Delete objects after 3 days** ко всему bucket. Это необходимо: R2 в отличие от KV **не удаляет объекты по KV TTL**. Сделай правило до запуска крупных роликов, иначе старые файлы будут накапливаться.
4. Cloudflare → **Workers & Pages** → свой существующий Worker → **Settings → Bindings** → добавь **R2 bucket binding**:
   - Variable name: `VIDEO_FILES`
   - Bucket: `ai-montage-private` (или фактическое имя созданного bucket)
5. Сохрани существующую KV-привязку **`UPLOADS`** и секреты `TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `GITHUB_PAT`.
6. Замени код Worker полным файлом **[`cloudflare_launcher_r2_v8.js`](./cloudflare_launcher_r2_v8.js)** и нажми **Deploy**. Используй именно v8 для больших файлов; старый `cloudflare_launcher.js` останется запасным вариантом KV.
7. Открой `https://ТВОЙ-WORKER.workers.dev/health`. Должно быть:
   ```json
   {"status":"online","style_contract_version":8,"large_storage_configured":true,"max_video_seconds":600,"storage_mode":"r2","max_upload_mb":4000}
   ```
8. Закрой и вновь открой Mini App. Проверь «Проверить подключённый Cloudflare».

## Почему это НЕ «неважно сколько МБ»

Cloudflare KV Free ограничен 1 ГБ хранения, поэтому его нельзя использовать как безлимитный склад видео. R2 позволяет хранить большие объекты, но имеет объём бесплатного использования и биллинг после него. Наш GitHub runner имеет ограниченный диск и 4 ядра/16 ГБ памяти, а при монтаже 10 минут может понадобиться **несколько полных промежуточных перекодирований**. Принять 4 ГБ и успешно обработать их — **разные вещи**; нужен тест на реальном видео после настройки. Для гарантированной работы с роликами значительно больше 4 ГБ нужен облачный сервер с большим диском и потоковой обработкой, который может быть платным.

Результат технического smoke-теста не подтверждает реальный рендер 10 минут: он только проверяет метаданные гигабайтных файлов, R2-чанки и защищённую выдачу.

## Где искать ошибки

[GitHub Actions](https://github.com/revuallrabota-coder/my-ai-video-editor/actions) → «📥 Монтаж до 10 минут» (историческое имя файла workflow — `.github/workflows/upload-video-50mb.yml` ради совместимости). При ошибке смотри последние строки рендера и [R2 storage usage](https://dash.cloudflare.com/) отдельно.
